# Stitch 设计稿参考说明

## 一、设计稿来源

当前 UI 原型来自 Stitch。

设计稿分为三期：

- Phase 1：MVP，双引擎记录面板与近 30 天聚合审计
- Phase 2：Core，自定义时间窗审计与错题本
- Phase 3：Scale，K 线时间轴打点与投资军规闭环

Codex 可以查看三期设计稿以理解长期方向，但当前只允许实现被明确指定的 Phase。

## 二、设计稿使用优先级

如果信息冲突，请按以下优先级判断：

1. `docs/PROJECT_BRIEF.md`
2. `docs/ROADMAP.md`
3. `docs/AI_BOUNDARY.md`
4. `docs/DESIGN_REFERENCE.md`
5. Stitch 截图
6. Stitch 生成代码
7. Stitch 在线链接

产品目标和 AI 边界优先于视觉稿。

## 三、视觉风格

默认风格与主题：

- 黑夜模式为默认视觉，保留原暗黑金融风
- 设置面板支持切换日间模式，并在当前浏览器持久保存
- 设置面板提供“请作者喝咖啡”入口，二维码弹窗需保留手机长按保存原图的能力
- 两套主题使用语义色变量，不允许为日间模式复制整套组件
- 日间模式使用冷白灰背景、白色内容面与深色正文，保持工具型界面
- 买入 / 正向：绿色
- 卖出 / 风险 / 错误：红色
- AI / 审计：靛蓝
- 字体风格：清晰、专业、数据感
- 移动端原生质感

## 四、移动端交互要求

禁止：

- Hover 态
- PC 表格优先
- 后台系统式布局
- 太多层级跳转
- 信息密度过高导致手机不可用

优先使用：

- Bottom Tab Bar
- Segmented Control
- Sticky Header
- Fixed Bottom CTA
- Accordion
- Chip / Badge
- Pressed State
- Empty State
- Full State

## 五、Phase 1 设计稿说明

Phase 1 包含两个底部 Tab：

1. 记录决策
2. 决策历史与审计

### 记录决策

包含两个子视图：

- 闪念手动输入
- AI 截图识图补账

手动输入必须保留：

- 买入 / 卖出 / 观察
- 标的名称
- 交易时间
- 预期止盈价
- 预期止损价
- 一句话决策理由
- 情绪标签
- 策略标签
- 保存按钮

AI 截图识图补账必须保留：

- 空状态上传区
- 完整数据态的批量识别结果
- 每笔交易可展开确认
- 允许用户修改交易时间
- 允许用户补写心理活动
- 允许用户选择情绪标签
- 批量归档按钮

### 决策历史与审计

必须保留：

- 空状态
- 近 30 天系统智能审计
- 最新审计结论
- 历史审计报告折叠列表
- 历史流水 Feed

## 八、Codex 实现要求

在写代码前，Codex 必须先回答：

1. 当前任务属于哪个 Phase？
2. 本轮只实现哪些页面？
3. 哪些设计元素可以简化？
4. 哪些字段需要为后续预留？
5. 哪些功能不得提前实现？
6. 会修改哪些文件？

不要直接复制 Stitch 生成代码。

Stitch 设计稿主要用于视觉、布局和交互参考，项目代码应保持清晰、可维护、组件化。
