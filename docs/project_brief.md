# RationalTrade / 理性交易笔记：项目总说明

## 一、项目目标

RationalTrade 是一个 AI 驱动的投资决策记录与复盘工具。

它不是传统的财务记账软件，也不是资产管理软件，更不是荐股工具。它的核心定位是：

> 面向个人投资者的交易者心理认知与执行力审计系统。

这个项目的第一目标是做成一个完整、可持续迭代的个人投资决策记录与复盘工具。

项目需要体现：

* 清晰的产品边界
* 移动端优先的交互体验
* 稳定的全栈工程实现
* 可控的 AI 能力集成
* 可解释的数据分析与 Dashboard
* 分阶段迭代规划
* 长期可维护的项目结构

## 二、核心问题

大多数个人投资者的问题并不是“没有记录交易”，而是：

* 当时为什么买/卖，事后记不清
* 明明有计划，但执行时被情绪带走
* 亏损后会重新解释自己的逻辑
* 高位追涨、低位割肉、听消息交易反复发生
* 只看单笔盈亏，无法识别长期行为模式
* 知道自己有问题，但没有工具持续审计自己的执行力

因此，本产品不只是记录“我买了什么”，而是记录：

> 我为什么在那个时间点做这个决定，当时的情绪是什么，后来是否遵守了原计划。

## 三、产品定位

RationalTrade 是一个交易决策复盘工具，而不是投资建议工具。

它应该帮助用户：

* 留存交易发生时的决策现场
* 记录当时的心理状态
* 记录操作理由和预期目标
* 通过 AI 总结可能的认知偏差
* 通过周期审计发现长期行为模式
* 通过错题本识别高频错误
* 通过投资军规约束后续执行

它不应该：

* 推荐股票
* 预测涨跌
* 给出买入/卖出/持有建议
* 主动给用户目标价
* 替用户做投资决策

## 四、设计理念

### 1. 留存决策现场

交易的关键往往发生在按下买卖键之前。

产品需要尽量降低记录门槛，让用户在操作发生时快速记录：

* 标的
* 操作方向
* 时间
* 价格
* 决策理由
* 情绪状态
* 止盈/止损预期
* 策略标签

核心不是追求完整财务字段，而是强制用户留下“当时的真实想法”。

### 2. 跨周期冷酷复盘

单笔交易具有噪音，真正有价值的是周期性行为模式。

产品需要支持 AI 在一段时间内进行聚合审计，例如：

* 大盘下跌时是否更容易焦虑
* 财报季是否更容易冲动交易
* 听消息交易是否贡献了主要亏损
* 是否反复在右侧情绪高点追高
* 是否在低位恐慌割肉
* 是否存在言行不一

### 3. 视觉语言

产品视觉应该专业、克制、数据驱动。

默认设计风格：

* 暗黑金融风
* 主色：`bg-slate-950`
* 卡片：`bg-slate-900`
* 强调色：红色代表风险/卖出/错误，绿色代表买入/正向，靛蓝代表 AI/审计
* 移动端原生质感
* Bottom Tab Bar
* 分段控制器
* 胶囊按钮
* 折叠卡片
* 空状态与完整数据态都必须设计

禁止：

* 过度 Web 化
* 依赖 Hover 交互
* 桌面端表格优先
* 让页面像普通记账 App
* 让页面像荐股 App

## 五、目标用户

### 主要用户

有股票、ETF、基金、期权等交易行为的个人投资者。

典型特征：

* 会在工作间隙、看盘时、新闻刺激下临时操作
* 容易受 FOMO、焦虑、不甘心、亏损厌恶影响
* 会事后美化或重构自己的交易理由
* 需要一个工具帮助自己客观复盘行为
* 不是专业交易员，但希望形成更稳定的投资纪律

## 六、核心产品闭环

第一层闭环：

记录交易决策
↓
AI 提取/总结决策理由和情绪
↓
用户确认并归档
↓
历史记录沉淀

第二层闭环：

历史记录积累
↓
AI 做近 30 天或自定义周期聚合审计
↓
发现情绪、策略和执行问题
↓
沉淀错题标签

第三层闭环：

错题与军规沉淀
↓
新交易触发军规检查
↓
AI 对用户进行决策审计和反问
↓
帮助用户减少重复犯错

## 七、项目交付目标

最终项目应该包括：

* 可运行的 Web/PWA 应用
* 移动端优先页面
* 手动记录交易
* AI 截图识图后的批量确认流程
* 历史记录
* 近 30 天智能审计
* 自定义周期审计
* 错题本 Dashboard
* 投资军规模块
* 示例数据
* 项目 README
* 架构说明
* 使用说明
* 基础截图或操作说明

## 八、当前技术方向

默认技术栈：

* Next.js
* React
* TypeScript
* Tailwind CSS
* shadcn/ui
* Supabase
* 服务端接口调用 LLM API
* PWA
* Web MVP 稳定后，再考虑 Capacitor 打包 Android

但该技术方向不是绝对的。

Codex 可以挑战技术选型，但必须说明：

* 为什么替换
* 替换后的收益
* 替换后的代价
* 对 MVP 进度的影响
* 对长期维护成本的影响
